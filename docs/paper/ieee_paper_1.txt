ABSTRACT
================================================================================
Desktop file search often fails when queries express conceptual intent rather than literal filenames. While dense embeddings capture semantic abstractions, they struggle with specialized identifiers; conversely, sparse inverted indices fail on conceptual paraphrases. Furthermore, commercial retrieval platforms rely heavily on cloud APIs, compromising personal data privacy. We present IntentCloud, a local-first, intent-aware document retrieval architecture designed for consumer hardware without external cloud dependencies. Ingested documents are indexed into a dual-stream representation combining 384-dimensional dense semantic vectors with 1,000,003-dimensional feature-hashed sparse token vectors. Parallel candidate streams are merged via Reciprocal Rank Fusion (k=60) and reranked using a cross-encoder model paired with an empirical confidence gate (tau = 0.40) for out-of-domain abstention and explainable citation attribution. The retrieval pipeline executes fully locally on consumer hardware, with an optional outbound Cloudflare Zero-Trust tunnel functioning strictly as an encrypted transport proxy. Evaluated across 175 documents (12,744 vectors in embedded Qdrant) partitioned into a 25-query development split, a 60-query held-out test split, 40 adversarial hard negatives, and 10 out-of-domain controls, IntentCloud achieves 96.7% Top-1 accuracy [95% CI: 88.7%–99.1%], 100.0% Top-3 accuracy, and 0.981 Mean Reciprocal Rank. The system significantly outperforms real BM25 (71.7% Top-1; p < 0.001) and dense bi-encoder baselines (73.3% Top-1; p < 0.001), while correctly rejecting 97.5% of adversarial hard negatives and demonstrating zero-shot generalization on the public BEIR/SciFact benchmark (NDCG@10 = 0.718).

INDEX TERMS:
Intent-aware retrieval, hybrid search, semantic search, reciprocal rank fusion, cross-encoder reranking, privacy-preserving retrieval.

I. INTRODUCTION
================================================================================
Modern computer users routinely store hundreds of heterogeneous documents--such 
as technical research papers, software architecture specifications, financial 
spreadsheets, lecture transcripts, and configuration manifests--across unorganized 
local directories. Locating specific files within these repositories using 
operating system search utilities remains an exercise in frustration. Traditional 
desktop file indexers and metadata-driven engines [1] rely on rigid lexical matching 
(e.g., filename substrings or basic grep-style token scans). When users recall only 
the conceptual intent or episodic context of a document (e.g., "the paper discussing 
stream processing backpressure" rather than an exact filename or technical identifier), 
keyword search yields zero matches.

To resolve this limitation, contemporary information retrieval has pivoted 
toward dense semantic search and Retrieval-Augmented Generation (RAG) paradigms 
powered by transformer-based encoders [2], [3]. A literature survey of nineteen 
recent works [1]-[19] identifies recurring operational trade-offs across current 
information retrieval and RAG paradigms:
1. Vocabulary Mismatch on Rare Tokens: Dense bi-encoders compress multi-token 
   passages into low-dimensional bottlenecks, frequently washing out critical 
   alphanumeric codes and acronyms [3], [4].
2. Privacy Leakage and Telemetry Exposure: Mainstream RAG solutions require 
   transmitting unencrypted local documents to third-party cloud LLM APIs [6], 
   [7], [9], violating enterprise data sovereignty and personal privacy.
3. Synthesis Over Retrieval: Commercial RAG interfaces generate synthesized 
   summaries rather than delivering the authoritative source file [9], [11].
4. Hallucination on Out-of-Domain Queries: Standard nearest-neighbor search 
   forces a top-k result regardless of query relevance [12].

To overcome these structural limitations, we introduce IntentCloud, an 
intent-aware, local-first document retrieval system designed to bridge the 
lexical-semantic gap through principled rank fusion and high-precision cross-encoder reranking.

KEY CONTRIBUTIONS:
(1) Privacy-Preserving Hybrid Retrieval (Obj. 1): Dual-stream pipeline combining 384-d dense embeddings and 1,000,003-d feature-hashed sparse token vectors unified via Reciprocal Rank Fusion (k=60) and cross-encoder reranking, validated against real BM25, competitive dense baselines, and isolated ablation variants.
(2) Fully Local, Portable Architecture (Obj. 2): End-to-end architecture executing ingestion, OCR, embedding, retrieval, and reranking entirely on consumer hardware without external APIs, with automated hardware detection across CPU, Apple Silicon MPS [19], and NVIDIA CUDA [18].
(3) Authoritative File Delivery & Security Boundary (Obj. 3): Self-hosted service streaming exact source files (PDF, DOCX, TXT). Reconciles local privacy with remote access: core cognitive pipeline executes 100% locally with zero external LLM transmission, while an optional outbound-only encrypted Cloudflare Zero-Trust tunnel acts strictly as an L4/L7 transport proxy (air-gapped when deactivated).
(4) Query-Aware Intent Parsing & Lineage Scoring (Obj. 4): Open-ended query intent distillation and metadata modeling, incorporating temporal decay and version lineage tracking (S_meta(d|q)) formally integrated into cross-encoder reranking via Eq. (5) to distinguish draft, parent, and latest document revisions.
(5) Calibrated Abstention & Statistical Rigor (Obj. 5): Confidence-gated decision mechanism (tau = 0.40) evaluated across a benchmark suite with 40 adversarial hard negatives, reporting 95% confidence intervals, McNemar's tests, and paired t-tests.
(6) Edge Profiling & Public Benchmark Generalization (Obj. 6): Operational latency and scaling evaluation on consumer workstations and Raspberry Pi 4 edge nodes, complemented by zero-shot generalization on the public BEIR/SciFact benchmark.

II. LITERATURE REVIEW & RESEARCH GAP
================================================================================
Information retrieval research has shifted from lexical matching (BM25, TF-IDF) 
toward dense transformer embeddings [2], [3] and Retrieval-Augmented Generation 
(RAG) pipelines [6], [7]. This section reviews nineteen works from our submitted 
literature survey [1]-[19], organized into four thematic categories.

A. Semantic Retrieval Systems
Karthikeyan et al. [1] proposed metadata-based smart document search using 
Kubernetes, requiring substantial infrastructure overhead. Vaswani et al. [2] 
introduced the transformer architecture underlying modern embedding models. 
Kumbam et al. [3] combined transformer embeddings with clustering and 
generative re-ranking but depend on large models unsuitable for edge deployment. 
Brundha and Meera [4] improved retrieval via embedding transformation but lack 
a complete serving pipeline. Douze et al. [5] presented FAISS for efficient vector 
search without persistence or upload infrastructure.

B. Retrieval-Augmented Generation
Krishnan and Subramanian [6] and Jacob et al. [7] demonstrated RAG relevance 
gains but require commercial cloud APIs and recurring costs. Sawarkar et al. [8] 
showed that blending dense and sparse retrieval outperforms either method alone. 
Rafi et al. [9] and Saha et al. [11] return synthesized answers rather than 
original files. Tiwari et al. [10] improved retrieval via fine-tuning but require 
GPU infrastructure. Cejas et al. [12] traced embedding quality impacts on RAG 
performance and top-k restriction effects.

C. Intent Classification and Intent-Aware Retrieval
Sriram et al. [13] used local LLMs for secure task automation but reported 14% 
misclassification and single-machine confinement. Kuchlous and Kadaba [14] 
restricted intent to four closed categories. Puspitasari et al. [15] proposed 
intent-aware RAG with semantics-preserving chunking but assume localized relevance 
and do not deliver source files.

D. Edge AI, Hardware Acceleration, and Deployment
Nan et al. [16] achieved strong retrieval with DSMR but require dual A100 GPUs 
and 128 GB RAM. Holubiev et al. [17] used autonomous agents without IR 
benchmarking. Nickolls et al. [18] and Apple Inc. [19] document CUDA and MPS 
acceleration backends integrated into IntentCloud's cross-platform inference.

E. Hybrid Fusion, Reranking, and Research Gap
IntentCloud adopts complementary dense bi-encoder retrieval [20], [21], 
sparse feature hashing [22], Okapi BM25 [23], Reciprocal Rank Fusion (k=60) [24], 
and cross-encoder reranking [25], [26], [27], [28]. Table I summarizes research 
gaps and IntentCloud's design responses.

Table I: Research Gaps and IntentCloud Response
- Cloud API & Privacy [6], [9]: 100% local ingestion, embedding, and retrieval
- Closed-set intent [14], [15]: Open-ended NL intent parsing (find, compare, list)
- Synthesis-only output [9], [11]: Returns original PDF/DOCX/TXT with citation snippets
- GPU-cluster requirement [16], [8]: Embedded Qdrant + cross-platform MPS/CUDA/CPU
- Incomplete deployment [5], [1]: End-to-end upload, index, search, and file streaming
- Remote access isolation [13]: Local memory with optional Zero-Trust transport tunnel

III. METHODOLOGY
================================================================================
Phase 1: Ingestion, Extraction, and Lineage vs. Dedup Resolution
Multi-format file upload support (PDF, DOCX, TXT) via PyMuPDF, python-docx, and 
Tesseract OCR fallback (<100 characters). 
Two-tier duplicate and lineage handling:
1. Exact Cryptographic Deduplication: SHA-256 duplicate uploads are rejected.
2. Semantic Version Lineage Preservation: Files with high semantic similarity (>= 0.95) 
   that possess distinct revision names (v1 vs v2) or modified timestamps are linked 
   in the metadata version graph (d_parent <- d_v1) and assigned version index v_d. 
   Only unversioned, timestamp-identical uploads with cosine similarity >= 0.98 are flagged.
   Chunk-to-file deduplication groups candidate passages by file_id during retrieval.

Phase 2: Dual Semantic and Lexical Vector Representation
1. Dense Semantic Embedding: all-MiniLM-L6-v2 (384-d, Wang et al. [26], Karpukhin et al. [20]).
2. Deterministic Sparse Feature Hashing: MurmurHash3 into D=1,000,003 dimensions (Weinberger et al. [22]).
Both indexed into embedded, in-process Qdrant vector database.

Phase 3: Query-Aware Intent Parsing and Lineage Conditioning
Local LLM (llama3.2:1b under Ollama, theta=0.1) extracts topic, keywords, intent_type, and temporal constraints.
Metadata lineage score:
  S_meta(d|q) = lambda_t(q) * T(d, q) + lambda_v(q) * V(d, q)               (Eq. 4)
where T(d, q) = exp(-gamma * Delta t) and V(d, q) in [-0.5, 0.5].

Phase 4: Hybrid Retrieval, Fusion, and Reranking
1. Parallel retrieval: Top 20 dense + Top 20 sparse candidates.
2. Reciprocal Rank Fusion: RRF_Score(d) = sum 1 / (k + r_m(d)), k=60 (Eq. 6). Top N=25 candidates.
3. Cross-Encoder Precision Reranking: ms-marco-MiniLM-L-6-v2 produces raw logit z(q, d), 
   mapped via sigmoid to probability s_ce(q, d).
4. Formally Defined Final Scoring (Eq. 5):
   S_final(q, d) = s_ce(q, d) * [1 + alpha * S_meta(d|q)]                    (Eq. 5)
   with coupling coefficient alpha = 0.25 (tuned on development split n=25).
5. Explainable Matched-Snippet Attribution: Highest-scoring sentence extracted and highlighted.
6. Calibrated Confidence Gating: If max S_final(q, d) >= tau = 0.40, serve Top-3; else Abstain.

Phase 5: Self-Hosted Delivery and Security Architecture Boundary
- Local Cognitive Boundary: 100% on-device. Zero bytes transmitted to external LLMs.
- Transport Proxy Boundary: Optional outbound-only encrypted Cloudflare Zero-Trust tunnel 
  acts strictly as an L4/L7 transport pipe. Zero indexing or inference occurs in the cloud. 
  In strictly air-gapped environments, the tunnel daemon is disabled.

================================================================================
V. RESULTS AND DISCUSSION
================================================================================
Quantitative Performance & Statistical Significance:
- Proposed pipeline achieves 96.7% Top-1 [95% CI: 88.7%–99.1%], 100% Top-3, 0.981 MRR.
- Outperforms Real BM25 (+25.0% Top-1, McNemar's chi^2 = 13.07, p = 0.0003 < 0.001; paired t-test t = 5.61, p < 0.0001).
- Outperforms Dense MiniLM (+23.4% Top-1, McNemar's chi^2 = 12.00, p = 0.0005 < 0.001; paired t-test t = 5.84, p < 0.0001).
- Outperforms Competitive Dense bge-small (+20.0% Top-1, McNemar's chi^2 = 9.31, p = 0.0023).

Ablation & Intent/Lineage Evaluation:
- Intent parser accuracy: 92.0% with llama3.2:1b JSON mode; 86.0% with regex fallback.
- Lineage ablation (Eq. 5): On 15 version queries, without lineage (alpha=0), Top-1 is 86.7% (13/15); 
  with Eq. (5) (alpha=0.25), Top-1 reaches 100.0% (15/15), lifting overall Top-1 from 93.3% to 96.7%.
- Hard Negatives: Rejects 97.5% (39/40) of adversarial queries; BM25 rejects only 17.5% (82.5% false positives).
- Public Benchmark Generalization: On BEIR/SciFact subset, Proposed Pipeline achieves NDCG@10 = 0.718 (+8.0% vs BM25) 
  and Recall@10 = 0.845 (+12.4% vs BM25).

Latency & Scaling:
- Local CPU latency: 160.2 ms (BM25: 1.3 ms, Dense ANN: 24.0 ms, RRF: 0.9 ms, Cross-Encoder: 130.1 ms, Citation: 3.9 ms).
- Raspberry Pi 4 (ARM Cortex-A72): 2.8 s end-to-end latency.
- Apple Silicon MPS / NVIDIA CUDA: < 20 ms.
- Memory: 180 MB RAM for 12,744 vectors in embedded Qdrant.

================================================================================
VI. LIMITATIONS
================================================================================
1. Edge Compute Latency and Thermal Limits: Cross-encoder reranking takes 2.8 s on Raspberry Pi 4; sustained batch queries require INT8 quantization or active cooling.
2. Cold-Start Ingestion Latency: Large multi-page scanned PDF OCR takes ~1.2 s per page on CPU (runs asynchronously).
3. Local LLM Consistency: llama3.2:1b JSON parsing achieves 92.0% accuracy; highly ambiguous queries trigger regex fallback.
4. Linguistic Scope: Currently evaluated on English-language technical repositories.

================================================================================
VII. CONCLUSION AND FUTURE WORK
================================================================================
IntentCloud bridges the lexical-semantic gap while guaranteeing strict personal data sovereignty. 
Achieves 96.7% Top-1 accuracy, 100% Top-3 accuracy, 0.981 MRR, 97.5% hard-negative rejection, and zero-shot 
public generalization (BEIR/SciFact NDCG@10 = 0.718).
Future work: INT8 quantization for sub-second Pi 4 inference, dynamic graph lineage traversal, and active-learning reranking.
