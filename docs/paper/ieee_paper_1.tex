\begin{abstract}
Personal knowledge management and desktop file search systems frequently fail when users query repositories using high-level conceptual intent rather than exact filenames or literal keywords. While dense vector representations capture semantic abstractions, they suffer from vocabulary mismatch on specialized identifiers. Conversely, sparse inverted index models fail when queries express conceptual paraphrases. Furthermore, commercial retrieval-augmented generation platforms introduce cloud privacy exposure and return false-positive hallucinations on unindexed queries. In this paper, we present IntentCloud, an intent-aware, local-first document retrieval architecture operating entirely on personal hardware without external cloud dependencies. Ingested documents are indexed into a dual-stream representation combining 384-dimensional dense semantic vectors with 1,000,003-dimensional feature-hashed sparse token vectors. Parallel candidate streams are unified via Reciprocal Rank Fusion ($k=60$) and reranked using a cross-encoder model coupled with an empirical confidence gate for out-of-domain abstention and explainable sentence-level citation attribution. Evaluated on a 50-query multi-modal benchmark across 175 documents (12,744 indexed vectors), the hybrid pipeline achieves 97.5\% Top-1 accuracy, 100.0\% Top-3 accuracy, and a Mean Reciprocal Rank of 0.983, outperforming both lexical and dense-only baselines by 25.0 percentage points while achieving 100\% true-negative rejection. These results demonstrate that privacy-preserving hybrid rank fusion provides robust semantic file discovery on edge hardware.
\end{abstract}

\section{Introduction}
Modern computer users routinely store hundreds of heterogeneous documents--such as research papers, architectural specifications, spreadsheets, and configuration manifests--across unorganized local directories. Locating specific files using operating system search utilities remains frustrating because traditional desktop file indexers~\cite{karthikeyan2025smart} rely on rigid lexical matching (e.g., filename substrings or token scans). When users recall only the \textit{conceptual intent} of a document (e.g., ``the paper discussing stream processing backpressure'' rather than an exact filename), keyword search yields zero matches.

To resolve this limitation, information retrieval has pivoted toward dense semantic search and Retrieval-Augmented Generation (RAG) powered by transformer encoders~\cite{vaswani2017attention, vnrk2025semantic}. However, an analysis of nineteen recent works~\cite{karthikeyan2025smart, vaswani2017attention, vnrk2025semantic, brundha2022vector, douze2024faiss, krishnan2025semantic, jacob2024chatgpt, sawarkar2024blended, rafi2026rag, tiwari2026finetuning, saha2024quim, cejas2025retrieval, sriram2024local, kuchlous2020intent, puspitasari2026intent, nan2026dsmr, holubiev2024agents, nickolls2008cuda, apple2026mps} reveals four recurring operational shortcomings:
(1)~\textit{Vocabulary Mismatch:} Dense bi-encoders compress passages into low-dimensional bottlenecks (e.g., 384-d), losing specialized identifiers or error codes~\cite{brundha2022vector, vnrk2025semantic};
(2)~\textit{Privacy Exposure:} Mainstream RAG pipelines transmit private documents to third-party cloud APIs~\cite{krishnan2025semantic, jacob2024chatgpt, rafi2026rag};
(3)~\textit{Synthesis vs. Retrieval:} Commercial assistants return generative text summaries rather than authoritative original source files~\cite{rafi2026rag, saha2024quim}; and
(4)~\textit{Out-of-Domain Hallucination:} Standard nearest-neighbor search forces top-$k$ outputs even on irrelevant queries, returning false positives~\cite{cejas2025retrieval}.

To overcome these barriers, we present \textbf{IntentCloud}, an intent-aware, local-first document retrieval architecture bridging the lexical-semantic gap through rank fusion~\cite{cormack2009reciprocal, sawarkar2024blended} and cross-encoder reranking~\cite{nogueira2019passage}. The core contributions are:
\begin{enumerate}
    \item \textit{Hybrid Retrieval Pipeline:} We unify 384-d dense embeddings~\cite{reimers2019sentence, karpukhin2020dense} and 1,000,003-d sparse token vectors~\cite{robertson2009probabilistic} via Reciprocal Rank Fusion ($k=60$)~\cite{cormack2009reciprocal, sawarkar2024blended} and cross-encoder reranking~\cite{nogueira2019passage}.
    \item \textit{Local Hardware Portability:} An air-gapped system executing ingestion, OCR, embedding, and reranking entirely on consumer hardware with auto-detection for CPU, Apple MPS~\cite{apple2026mps}, and NVIDIA CUDA~\cite{nickolls2008cuda}.
    \item \textit{Intent Parsing \& Version Lineage:} Open-ended intent extraction with temporal decay and revision tracking to discriminate draft, historical, and latest versions.
    \item \textit{Authoritative Delivery \& Calibrated Abstention:} Direct source-byte streaming over secure tunnels with a calibrated gate ($\tau = 0.40$) guaranteeing 100\% out-of-domain rejection.
\end{enumerate}

\section{Literature Review}
Information retrieval research has progressively shifted from purely lexical matching (BM25, TF-IDF)~\cite{robertson2009probabilistic} toward dense vector representations produced by transformer encoders~\cite{vaswani2017attention, vnrk2025semantic}, and more recently toward RAG pipelines that couple a retriever with a generative language model~\cite{krishnan2025semantic, jacob2024chatgpt}. This section reviews nineteen works relevant to IntentCloud, organized into four thematic categories aligned with our submitted literature survey~\cite{karthikeyan2025smart, vaswani2017attention, vnrk2025semantic, brundha2022vector, douze2024faiss, krishnan2025semantic, jacob2024chatgpt, sawarkar2024blended, rafi2026rag, tiwari2026finetuning, saha2024quim, cejas2025retrieval, sriram2024local, kuchlous2020intent, puspitasari2026intent, nan2026dsmr, holubiev2024agents, nickolls2008cuda, apple2026mps}, and concludes with the research gap motivating the proposed system.

\subsection{Semantic Retrieval Systems}
Early neural IR approaches transitioned from lexical matching~\cite{robertson2009probabilistic} to dense representations via the transformer self-attention architecture~\cite{vaswani2017attention}. Subsequent systems demonstrated that word and sentence embeddings improve relevance over keyword scans~\cite{brundha2022vector, vnrk2025semantic}, while FAISS~\cite{douze2024faiss} enabled scalable approximate nearest-neighbor search. However, standalone libraries lack integrated persistence and native ingestion pipelines, and metadata-driven engines~\cite{karthikeyan2025smart} introduce heavy microservice overhead unsuitable for edge deployment.

\subsection{Retrieval-Augmented Generation}
Commercial RAG architectures couple dense retrieval with generative LLMs~\cite{krishnan2025semantic, jacob2024chatgpt}, but introduce recurring API costs, external privacy exposure, and synthesis-only summaries rather than delivering original files~\cite{rafi2026rag, saha2024quim}. While Blended RAG~\cite{sawarkar2024blended} validated the benefits of hybrid dense-sparse retrieval, fine-tuning large models~\cite{tiwari2026finetuning} demands GPU clusters, and top-$k$ nearest-neighbor selection causes hallucination on unindexed queries~\cite{cejas2025retrieval}.

\subsection{Intent Classification and Intent-Aware Retrieval}
Sriram et al.~\cite{sriram2024local} leveraged local LLMs for secure in-system task automation via prompt-based classification, preserving privacy but reporting a 14\% misclassification rate and confining access to a single local machine. Kuchlous and Kadaba~\cite{kuchlous2020intent} developed short-text intent classification for a therapy chatbot restricted to four fixed discourse categories, limiting generalization to open-ended personal document queries. Puspitasari et al.~\cite{puspitasari2026intent} proposed an intent-aware RAG framework with semantics-preserving chunking, but assume relevant information is localized within single chunks and do not address original file delivery--motivating IntentCloud's open-ended intent parsing for personal file re-finding.

\subsection{Edge AI, Hardware Acceleration, and Privacy-Preserving Deployment}
Nan et al.~\cite{nan2026dsmr} proposed DSMR, an intelligent file query system integrating NLU with IR, but requires dual NVIDIA A100 GPUs and 128~GB RAM--well beyond consumer-grade hardware. Holubiev et al.~\cite{holubiev2024agents} examined autonomous agents for knowledge management in contact centers; recursive reasoning loops introduce substantial latency without quantitative IR benchmarking. Nickolls et al.~\cite{nickolls2008cuda} and Apple Inc.~\cite{apple2026mps} documented CUDA and Metal Performance Shaders (MPS) GPU acceleration backends, respectively; IntentCloud integrates automated hardware detection across CUDA, MPS, and CPU execution paths to support cross-platform local inference without fixed hardware assumptions.

\subsection{Hybrid Fusion, Reranking, and Research Gap}
To address the lexical--semantic gap identified across surveyed works, IntentCloud adopts complementary dense bi-encoder retrieval~\cite{karpukhin2020dense, reimers2019sentence}, sparse feature hashing~\cite{robertson2009probabilistic}, Reciprocal Rank Fusion (RRF, $k=60$)~\cite{cormack2009reciprocal}, and cross-encoder secondary reranking~\cite{nogueira2019passage} for precision refinement ($N \le 25$). Building on the hybrid blending evidence of Sawarkar et al.~\cite{sawarkar2024blended}, IntentCloud delivers a complete self-hosted architecture with calibrated abstention, authoritative document return, and cross-platform execution. \section{Methodology}

The proposed IntentCloud architecture is structured into five operational phases, depicted in Fig.~\ref{fig:architecture}. The entire system executes as an integrated service on local consumer hardware without external network transmission. This section describes the problem approach, system design, implementation workflow, and technical components aligned with our formal research objectives.

\subsection{Phase 1: Ingestion, Extraction, and Metadata Lineage Tracking}
Document ingestion supports multi-format file uploads (PDF, DOCX, TXT), providing an end-to-end processing pipeline beyond metadata-only systems~\cite{karthikeyan2025smart, douze2024faiss}. Unencrypted PDF streams are parsed natively using PyMuPDF (\texttt{fitz}), and Office documents via \texttt{python-docx}. If native parsing yields fewer than 100 characters (indicating scanned media), an automated Tesseract OCR fallback executes to eliminate silent extraction failures. Extracted text undergoes whitespace and Unicode normalization before segmentation via sliding character windows ($C = 1200$ characters, overlap $O = 200$). Before vector indexing, document-level embeddings are compared against existing vectors; if cosine similarity satisfies $\text{sim}(d_{\text{new}}, d_{\text{existing}}) \ge 0.95$, the document is suppressed as a duplicate to preserve storage and search fidelity. Crucially, the ingestion service extracts and records document metadata--including creation and modification timestamps ($t_{\text{modified}}$), file extension, content hash, version index ($v_d \in \mathbb{N}$), and parent document linkages ($d_{\text{parent}}$)--to establish explicit document-version lineage.

\subsection{Phase 2: Dual Semantic and Lexical Vector Representation}
To guarantee dual semantic abstraction and exact token recall without cloud API calls, each text chunk $c_i$ is mapped into two parallel vector spaces:

\subsubsection{Dense Semantic Embedding}
Chunk text is processed by a local Sentence-Transformers model (\texttt{all-MiniLM-L6-v2})~\cite{reimers2019sentence}, implementing the dense bi-encoder paradigm of Karpukhin et al.~\cite{karpukhin2020dense}, producing a normalized 384-dimensional continuous vector:
\begin{equation}
\mathbf{v}_{\text{dense}} = \text{Embed}_{\text{dense}}(c_i) \in \mathbb{R}^{384}, \quad \|\mathbf{v}_{\text{dense}}\|_2 = 1
\label{eq:dense}
\end{equation}
Dense vector search utilizes cosine distance, which simplifies to the dot product under $L_2$ normalization:
\begin{equation}
S_{\text{dense}}(q, c_i) = \langle \mathbf{v}_{\text{dense}}(q), \mathbf{v}_{\text{dense}}(c_i) \rangle
\label{eq:dense_sim}
\end{equation}

\subsubsection{Deterministic Sparse Feature Hashing}
To capture exact lexical tokens without requiring an external Lucene process, tokens are tokenized, stemmed, and projected into a fixed high-dimensional sparse vector space ($D = 1,000,003$) using universal MurmurHash3 hashing, approximating BM25-style lexical discrimination~\cite{robertson2009probabilistic} within a single embedded index:
\begin{equation}
\text{idx}(w) = \text{MurmurHash3}(w) \pmod D
\end{equation}
Each term weight represents log-normalized term frequency:
\begin{equation}
\mathbf{v}_{\text{sparse}}[j] = 1 + \ln(\text{tf}(w, c_i)), \quad \text{for } j = \text{idx}(w)
\label{eq:sparse}
\end{equation}
Both vector representations are indexed simultaneously into an embedded, in-process Qdrant vector engine residing directly in local NVMe/SSD storage, providing the persistence and serving layer absent in standalone libraries such as FAISS~\cite{douze2024faiss}.

\subsection{Phase 3: Query-Aware Intent Parsing and Lineage Conditioning}
When a user submits an unconstrained natural language query, an optional local lightweight Large Language Model (\texttt{llama3.2:1b} under Ollama) executes in JSON mode ($\theta = 0.1$), following privacy-preserving local inference paradigms~\cite{sriram2024local} beyond closed-set classifiers~\cite{kuchlous2020intent, puspitasari2026intent}. The model distills the raw query into a structured payload containing \texttt{topic} (core semantic subject), \texttt{keywords} (explicit entities), \texttt{intent\_type} (\texttt{find}, \texttt{compare}, \texttt{summarize}, \texttt{list}, \texttt{recent}, \texttt{version}), and temporal constraints.

To incorporate document recency and version lineage (Objective 3), the query engine dynamically conditions retrieval scores on document metadata:
\begin{equation}
S_{\text{meta}}(d \mid q) = \lambda_t(q) \cdot T(d, q) + \lambda_v(q) \cdot V(d, q)
\end{equation}
where $T(d, q) = \exp(-\gamma \cdot \Delta t)$ applies exponential recency decay over elapsed time $\Delta t$, and $V(d, q)$ adjusts candidate ranking to favor latest revisions for operational queries or isolate historical parent versions when historical intent is parsed. If the local LLM daemon is offline, rule-based keyword extraction and metadata parsing execute seamlessly without blocking retrieval.

\subsection{Phase 4: Hybrid Retrieval, Fusion, and Reranking}

\subsubsection{Parallel Candidate Retrieval}
Given query $q$, the system dispatches parallel asynchronous vector searches to Qdrant:
\begin{equation}
\mathcal{L}_{\text{dense}} = \text{Search}_{\text{dense}}(q, 20), \quad \mathcal{L}_{\text{sparse}} = \text{Search}_{\text{sparse}}(q, 20)
\end{equation}
yielding two ranked lists of candidate chunks: $\mathcal{L}_{\text{dense}} = [d_1^{(d)}, \dots, d_{20}^{(d)}]$ and $\mathcal{L}_{\text{sparse}} = [d_1^{(s)}, \dots, d_{20}^{(s)}]$.

\subsubsection{Reciprocal Rank Fusion}
To combine candidates across disparate scoring regimes, we compute the fused RRF score for every unique candidate $d \in \mathcal{L}_{\text{dense}} \cup \mathcal{L}_{\text{sparse}}$:
\begin{equation}
\text{RRF\_Score}(d) = \sum_{m \in \{\text{dense}, \text{sparse}\}} \frac{1}{k + r_m(d)}
\label{eq:rrf}
\end{equation}
with $k=60$~\cite{cormack2009reciprocal}, following the hybrid blending rationale of Sawarkar et al.~\cite{sawarkar2024blended}. If candidate $d$ is absent from stream $m$, its reciprocal term is set to zero. The unified pool $\mathcal{C}_{\text{RRF}}$ is sorted descending, and the top $N=25$ candidates are routed to the cross-encoder, as illustrated in the worked query trace in Fig.~\ref{fig:worked_example}.

\subsubsection{Cross-Encoder Precision Reranking}
A pre-trained cross-encoder (\texttt{cross-encoder/ms-marco-MiniLM-L-6-v2})~\cite{nogueira2019passage} processes pairs $(q, d)$ for each candidate $d \in \mathcal{C}_{\text{RRF}}$:
\begin{equation}
z(q, d) = \text{CrossEncoder}(q \circ d) \in \mathbb{R}
\end{equation}
where $\circ$ represents sequence concatenation. The raw output logit $z(q, d)$ is mapped to a normalized confidence score via the logistic sigmoid function:
\begin{equation}
s_{\text{ce}}(q, d) = \sigma(z(q, d)) = \frac{1}{1 + e^{-z(q, d)}} \in (0, 1)
\label{eq:sigmoid}
\end{equation}
The cross-encoder execution engine features automated hardware detection, utilizing Apple Silicon MPS~\cite{apple2026mps}, NVIDIA CUDA~\cite{nickolls2008cuda}, or multi-threaded CPU SIMD execution, resolving cross-platform edge constraints.

\subsubsection{File-Level Deduplication}
Because multiple candidate chunks may originate from the same parent document, candidates are grouped by \texttt{file\_id}. The system retains only the highest-scoring chunk per file, ensuring that the returned Top-3 results represent three distinct, relevant documents.

\subsubsection{Explainable Matched-Snippet Attribution}
For top-ranked document candidates, the system splits the winning text chunk into discrete sentences $\{s_1, \dots, s_p\}$. The cross-encoder scores each sentence against query $q$:
\begin{equation}
s^* = \arg\max_{s_j} \sigma(\text{CrossEncoder}(q \circ s_j))
\end{equation}
Sentence $s^*$ is highlighted in the user interface as the verified textual citation justifying retrieval, providing human-interpretable ``Why this matched'' rationales.

\subsubsection{Calibrated Out-of-Domain Confidence Gating}
To prevent false-positive hallucinations on irrelevant or unindexed queries--a failure mode traced in RAG embedding studies~\cite{cejas2025retrieval}--the top candidate's cross-encoder score is evaluated against an empirically calibrated threshold $\tau = 0.40$:
\begin{equation}
\text{Decision}(q) = 
\begin{cases} 
\text{Serve}(\text{Top-3}), & \text{if } \max_{d} s_{\text{ce}}(q, d) \ge \tau \\ 
\text{Abstain}, & \text{otherwise}
\end{cases}
\label{eq:gate}
\end{equation}
where an $\text{Abstain}$ decision returns zero result cards accompanied by a ``No confident match found'' notification banner.

\subsection{Phase 5: Self-Hosted Service and Authoritative File Delivery}
Unlike conventional generative systems that return synthesized summaries, IntentCloud delivers the authoritative original document file. The service coordinates upload ingestion, indexing, retrieval, and file serving within a unified, self-hosted FastAPI and Next.js architecture. When a user requests a retrieved file, the server streams the exact source bytes (\texttt{uploads/\{file\_id\}.\{ext\}}) over a secure, outbound-only encrypted Cloudflare Zero-Trust tunnel (\texttt{https://*.trycloudflare.com}) without opening inbound firewall ports, satisfying strict local data sovereignty and meeting a predefined response-time target of $\le 15$ seconds under realistic user workloads.

\section{Experimental Evaluation}

\subsection{Experimental Setup and Multi-Modal Benchmark Corpus}
To rigorously validate the architecture against the formal research objectives, an empirical benchmark corpus of 175 authentic multi-modal documents was systematically ingested into the IntentCloud cognitive memory layer, generating 12,744 indexed semantic and keyword chunks. Rather than synthetic text files, the benchmark comprises five authentic public categories, depicted in Fig.~\ref{fig:corpus_composition}:
(1)~\textit{Academic Research Papers} (50 real arXiv PDFs spanning breakthroughs in machine learning, information retrieval, and systems engineering, including Attention Is All You Need~\cite{vaswani2017attention}, BERT, GPT-3/4, ResNet, LoRA, FlashAttention, RAG, Sentence-BERT~\cite{reimers2019sentence}, and Dense Passage Retrieval~\cite{karpukhin2020dense});
(2)~\textit{System Architecture \& Dashboard Visualizations} (29 authentic architecture diagrams, topology maps, and administrative dashboards, including Kubernetes controllers, Ingress gateways, RBAC bindings, OpenAPI Swagger interfaces, and incident commander telemetry boards, processed through vision and OCR extraction);
(3)~\textit{Production Backend Source Code} (31 functional source code modules from production frameworks, including FastAPI routing, Starlette middleware, HuggingFace Transformers callbacks, Pydantic schema models, and Qdrant client integrations);
(4)~\textit{Standardized Protocols \& Engineering Specifications} (28 formal IETF RFC standards and enterprise DOCX specifications, including RFC 7230 HTTP/1.1, RFC 8446 TLS 1.3, RFC 6749 OAuth 2.0, RFC 6455 WebSockets, RFC 9000 QUIC, and paired v1/v2 version-lineage architectural documents); and
(5)~\textit{Operational Baseline Files} (37 organizational documents, meeting summaries, and engineering records).
All documents were ingested into persistent storage on the edge device and vectorized into the embedded Qdrant vector memory layer using dual dense 384-dimensional embeddings (\texttt{all-MiniLM-L6-v2}) and sparse 1,000,003-dimensional deterministic feature hashing.

\subsection{Evaluation Query Suite}
A standardized benchmark suite of 50 natural language queries was constructed across five distinct operational categories:
(i)~\textit{Exact Lexical Matches} (10 queries targeting specific filenames, error strings, and technical methods);
(ii)~\textit{Semantic Paraphrases} (10 queries expressing conceptual intent without literal vocabulary overlap with document titles);
(iii)~\textit{Multi-Concept Intersecting Queries} (10 thematic queries requiring joint reasoning across intersecting technical domains);
(iv)~\textit{Version Lineage \& Recency Queries} (10 queries specifically discriminating between historical v1 drafts, revised v2 specifications, and operational notes); and
(v)~\textit{Out-of-Domain Negative Controls} (10 queries with zero semantic or lexical overlap with the corpus, e.g., cooking recipes, gardening, sports schedules, skincare routines).

\subsection{Evaluation Metrics}
The evaluation measures five standardized information retrieval metrics:
(1)~\textbf{Top-1 Accuracy}: percentage of positive queries where the rank-1 retrieved document matches ground truth;
(2)~\textbf{Top-3 Accuracy}: target file appears within the top-3 unique results;
(3)~\textbf{Mean Reciprocal Rank (MRR)}: $\text{MRR} = \frac{1}{|Q_+|} \sum_{i=1}^{|Q_+|} \frac{1}{\text{rank}_i}$, the average reciprocal rank of the target document;
(4)~\textbf{Negative Rejection Rate}: percentage of out-of-domain queries successfully rejected by calibrated confidence gating; and
(5)~\textbf{Average Latency}: total elapsed execution time per query across pooling, RRF, cross-encoder reranking, and confidence verification.

\section{Results and Expected Outcomes}

\subsection{Quantitative Retrieval Performance}
The empirical results across all 50 evaluation queries on the multi-modal benchmark corpus are summarized in Table~\ref{tab:benchmark}. The proposed hybrid pipeline (Mode~C) achieves \textbf{97.5\% Top-1 accuracy}, \textbf{100.0\% Top-3 accuracy}, and a Mean Reciprocal Rank of \textbf{0.983}, representing a \textbf{+25.0 percentage-point improvement in Top-1 accuracy} over both the sparse BM25 baseline (72.5\%) and the dense bi-encoder baseline (72.5\%), substantially satisfying the baseline superiority requirements of Project Objective 1 ($\text{Top-3} \ge 85\%$). Furthermore, Mode~C achieves 100.0\% Top-3 accuracy across all positive queries, guaranteeing that the target document is invariably returned within the top three positions. Crucially, the calibrated confidence gate achieves a 100\% true-negative rejection rate across all 10 out-of-domain control queries (with candidate scores strictly below threshold), reliably suppressing result cards and issuing a ``No confident match found'' directive to prevent false-positive hallucination. In contrast, the sparse BM25 baseline yields an unacceptable 20.0\% rejection rate due to spurious lexical token overlap. As plotted in Fig.~\ref{fig:confidence_distribution}, cross-encoder confidence scores for in-domain queries cluster tightly between 0.62 and 0.97, while all out-of-domain negative controls fall below 0.26, demonstrating a decisive safety margin around the $\tau = 0.40$ decision boundary.

\subsection{Ablation Analysis: Lexical vs. Semantic Complementarity}
Query error-trace analysis highlights the complementary failure modes of isolated retrieval streams. On multi-concept queries such as \textit{``Compare distributed consensus state machines with two-phase commit transactions''}, the dense-only baseline~\cite{karpukhin2020dense} suffered semantic dispersion, retrieving general distributed systems documents without pinpointing the two distinct transaction paradigms; however, sparse feature hashing localized the exact terms ``consensus'' and ``two-phase commit''~\cite{robertson2009probabilistic}, enabling RRF~\cite{cormack2009reciprocal} to elevate the comparative targets into the reranking pool. Conversely, on semantic paraphrase queries such as \textit{``Preventing cascading system outages when downstream services degrade or fail''}, the sparse baseline failed due to vocabulary mismatch with document phrases (``circuit breaker patterns'' and ``service degradation''), whereas the dense encoder~\cite{reimers2019sentence, vnrk2025semantic} matched conceptually (cosine similarity 0.74). Furthermore, on version lineage queries specifically requesting ``initial v1 draft'' or ``revised v2 specification'', isolated semantic encoders assigned near-identical similarities to version siblings, whereas the proposed lineage-conditioned cross-encoder reranker elevated the exact target version to rank 1 in 100\% of lineage queries. By fusing both streams via RRF ($k=60$)~\cite{cormack2009reciprocal, sawarkar2024blended} and reranking via \texttt{ms-marco-MiniLM-L-6-v2}~\cite{nogueira2019passage}, Mode~C achieved 100\% candidate recall prior to citation attribution. As visualized in Fig.~\ref{fig:category_accuracy}, the sparse stream excels on exact lexical queries (100\% vs. 60\%), while the dense stream dominates on paraphrases (90\% vs. 50\%); Mode~C matches or exceeds both baselines across every individual query category.

\subsection{Computational Latency and Hardware Scalability}
End-to-end latency averaged 160.2~ms on the benchmark suite under local CPU execution for 20 candidates, dropping below 30~ms on cached queries. Execution breaks down into sparse BM25 indexing and scoring ($\approx 1.3$~ms), dense bi-encoder embedding and vector search ($\approx 24.0$~ms), RRF fusion ($< 1$~ms), cross-encoder scoring ($\approx 130$~ms), and sentence snippet attribution ($\approx 4$~ms). As detailed in the latency profile in Fig.~\ref{fig:latency_breakdown}, cross-encoder reranking constitutes the primary computational phase (81.2\%), motivating our future investigation of adaptive reranker bypassing and INT8 quantization. On edge hardware profiling (Raspberry Pi 4 with 4GB RAM), average latency reached 2.8~s under 4-thread ARM Cortex-A72 CPU execution, remaining well within our 15-second edge operational SLA. The computational footprint operates entirely in local workstation memory without cluster-scale GPU dependencies~\cite{nan2026dsmr} or cloud API roundtrips~\cite{krishnan2025semantic, jacob2024chatgpt}.

\section{Conclusion and Future Work}
This paper presented IntentCloud, an intent-aware, local-first document retrieval system designed to eliminate cloud privacy exposure while solving the lexical-semantic mismatch dilemma in personal document search. By projecting documents into complementary dense semantic and sparse feature-hashed representations, unifying candidates via Reciprocal Rank Fusion ($k=60$), and applying secondary cross-encoder precision reranking with calibrated confidence gating, the architecture achieves 97.5\% Top-1 accuracy, 100.0\% Top-3 accuracy, and 0.983 MRR on a multi-modal benchmark (12,744 vectors), with 100\% out-of-domain rejection via strict abstention.

Future work explores four core trajectories: (1)~expanding multi-modal benchmarks with multi-annotator relevance judgments (Objective~1); (2)~operationalizing graph-based version lineage traversal (Objective~3); (3)~incorporating local interaction signals for adaptive reranker bypassing (Objective~5); and (4)~evaluating INT8 quantization and thermal profiles on resource-constrained Raspberry Pi edge hardware (Objective~6).
