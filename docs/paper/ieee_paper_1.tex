\begin{abstract}
Personal knowledge management and desktop file search systems frequently fail when users query repositories using high-level conceptual intent rather than exact filenames or literal keywords. While dense vector representations capture semantic abstractions, they suffer from vocabulary mismatch on specialized identifiers. Conversely, sparse inverted index models fail when queries express conceptual paraphrases. Furthermore, commercial retrieval-augmented generation platforms introduce external cloud privacy risks and return false-positive hallucinations on unindexed queries. In this paper, we present IntentCloud, an intent-aware, local-first document retrieval architecture operating entirely on consumer workstations without external cloud dependencies. Ingested documents are indexed into a dual-stream representation combining 384-dimensional dense semantic vectors with 1,000,003-dimensional feature-hashed sparse token vectors. Parallel candidate streams are unified via Reciprocal Rank Fusion ($k=60$) and reranked using a cross-encoder model coupled with an empirical confidence gate for out-of-domain abstention and explainable sentence-level citation attribution. Evaluated on a 42-query diagnostic benchmark comprising 32 positive natural-language queries and 10 negative controls, the hybrid pipeline achieves 87.5\% Top-1 accuracy, 100\% Top-3 accuracy, and a Mean Reciprocal Rank of 0.932, outperforming dense-only retrieval by 21.9 percentage points while rejecting all out-of-domain queries. These results demonstrate that privacy-preserving hybrid rank fusion provides robust semantic file search on personal hardware.
\end{abstract}

\begin{IEEEkeywords}

\section{Introduction}
Modern computer users routinely store hundreds of heterogeneous documents--such as technical research papers, software architecture specifications, financial spreadsheets, lecture transcripts, and configuration manifests--across unorganized local directories. Locating specific files within these repositories using operating system search utilities remains an exercise in frustration. Traditional desktop file indexers and metadata-driven engines~\cite{karthikeyan2025smart} rely on rigid lexical matching (e.g., filename substrings or basic grep-style token scans). When users recall only the \textit{conceptual intent} or episodic context of a document (e.g., ``the paper discussing stream processing backpressure'' rather than an exact filename or technical identifier), keyword search yields zero matches.

To resolve this limitation, contemporary information retrieval has pivoted toward dense semantic search and Retrieval-Augmented Generation (RAG) paradigms powered by transformer-based encoders~\cite{vaswani2017attention, vnrk2025semantic}. A structured literature survey of nineteen recent works~\cite{karthikeyan2025smart, vaswani2017attention, vnrk2025semantic, brundha2022vector, douze2024faiss, krishnan2025semantic, jacob2024chatgpt, sawarkar2024blended, rafi2026rag, tiwari2026finetuning, saha2024quim, cejas2025retrieval, sriram2024local, kuchlous2020intent, puspitasari2026intent, nan2026dsmr, holubiev2024agents, nickolls2008cuda, apple2026mps} identifies recurring operational trade-offs across current information retrieval and RAG paradigms:
\begin{enumerate}
    \item \textbf{Vocabulary Mismatch on Rare Tokens:} Dense bi-encoders compress multi-token passages into low-dimensional bottlenecks (e.g., 384 or 768 dimensions), frequently washing out critical alphanumeric codes, function names, error constants, or acronyms~\cite{brundha2022vector, vnrk2025semantic}.
    \item \textbf{Privacy Leakage and Telemetry Exposure:} Mainstream RAG solutions require transmitting unencrypted local documents to third-party cloud LLM APIs~\cite{krishnan2025semantic, jacob2024chatgpt, rafi2026rag}, violating enterprise data sovereignty and personal privacy regulations.
    \item \textbf{Synthesis Over Retrieval:} Commercial RAG interfaces generate synthesized textual summaries rather than directly retrieving and delivering the authoritative, untampered source file~\cite{rafi2026rag, saha2024quim}.
    \item \textbf{Hallucination on Out-of-Domain Queries:} Standard nearest-neighbor search algorithms force a top-$k$ nearest vector result regardless of query relevance, returning misleading false-positive documents when the user asks an irrelevant or unindexed question~\cite{cejas2025retrieval}.
\end{enumerate}

To overcome these structural limitations, we introduce \textbf{IntentCloud}, an intent-aware, local-first document retrieval system designed to bridge the lexical-semantic gap through principled rank fusion~\cite{cormack2009reciprocal, sawarkar2024blended} and high-precision cross-encoder reranking~\cite{nogueira2019passage}. 

\subsection{Key Contributions}
The core technical contributions of this research, structured to address our formal project objectives, are summarized as follows:
\begin{itemize}
    \item \textbf{Privacy-Preserving Hybrid Retrieval:} We design and implement a dual-stream retrieval pipeline combining 384-dimensional dense semantic embeddings~\cite{reimers2019sentence, karpukhin2020dense} and 1,000,003-dimensional feature-hashed sparse token vectors~\cite{robertson2009probabilistic} unified via Reciprocal Rank Fusion ($k=60$)~\cite{cormack2009reciprocal, sawarkar2024blended} and cross-encoder reranking~\cite{nogueira2019passage}, systematically evaluated against keyword-only and dense-only baselines.
    \item \textbf{Fully Local, Portable Architecture:} We develop an end-to-end architecture executing ingestion, OCR, embedding, retrieval, and reranking entirely on consumer hardware without third-party LLM APIs, featuring automated hardware detection across CPU, Apple Silicon MPS~\cite{apple2026mps}, and NVIDIA CUDA~\cite{nickolls2008cuda}.
    \item \textbf{Query-Aware Retrieval and Metadata Lineage:} We integrate open-ended query intent distillation and document metadata modeling, incorporating temporal recency and version lineage tracking to distinguish relevant, original, historical, and latest document versions.
    \item \textbf{Self-Hosted Original Document Delivery:} We provide a self-hosted document service supporting upload, indexing, retrieval, and direct authoritative file delivery (PDF, DOCX, TXT) over encrypted outbound tunnels within a predefined response-time SLA.
    \item \textbf{Adaptive Reranking and Calibrated Abstention:} We implement a confidence-gated decision mechanism ($\tau = 0.40$) and selective reranking framework grounded in local interaction signals, eliminating false-positive hallucinations on out-of-domain queries and minimizing redundant edge compute.
    \item \textbf{Edge Deployment and Empirical Profiling Roadmap:} We establish an optimization pathway for Raspberry Pi-class edge hardware, defining empirical characterization protocols across retrieval quality, latency, memory consumption, thermal behavior, throughput, and energy consumption.
\end{itemize}

\section{Literature Review}
Information retrieval research has progressively shifted from purely lexical matching (BM25, TF-IDF)~\cite{robertson2009probabilistic} toward dense vector representations produced by transformer encoders~\cite{vaswani2017attention, vnrk2025semantic}, and more recently toward RAG pipelines that couple a retriever with a generative language model~\cite{krishnan2025semantic, jacob2024chatgpt}. This section reviews nineteen works relevant to IntentCloud, organized into four thematic categories aligned with our submitted literature survey~\cite{karthikeyan2025smart, vaswani2017attention, vnrk2025semantic, brundha2022vector, douze2024faiss, krishnan2025semantic, jacob2024chatgpt, sawarkar2024blended, rafi2026rag, tiwari2026finetuning, saha2024quim, cejas2025retrieval, sriram2024local, kuchlous2020intent, puspitasari2026intent, nan2026dsmr, holubiev2024agents, nickolls2008cuda, apple2026mps}, and concludes with the research gap motivating the proposed system.

\subsection{Semantic Retrieval Systems}
Early neural IR approaches transitioned from lexical matching~\cite{robertson2009probabilistic} to dense representations via the transformer self-attention architecture~\cite{vaswani2017attention}. Subsequent systems demonstrated that word and sentence embeddings improve relevance over keyword scans~\cite{brundha2022vector, vnrk2025semantic}, while FAISS~\cite{douze2024faiss} enabled scalable approximate nearest-neighbor search. However, standalone libraries lack integrated persistence and native ingestion pipelines, and metadata-driven engines~\cite{karthikeyan2025smart} introduce heavy microservice overhead unsuitable for edge deployment.

\subsection{Retrieval-Augmented Generation}
Commercial RAG architectures couple dense retrieval with generative LLMs~\cite{krishnan2025semantic, jacob2024chatgpt}, but introduce recurring API costs, external privacy exposure, and synthesis-only summaries rather than delivering original files~\cite{rafi2026rag, saha2024quim}. While Blended RAG~\cite{sawarkar2024blended} validated the benefits of hybrid dense-sparse retrieval, fine-tuning large models~\cite{tiwari2026finetuning} demands GPU clusters, and top-$k$ nearest-neighbor selection causes hallucination on unindexed queries~\cite{cejas2025retrieval}.

\subsection{Intent Classification and Intent-Aware Retrieval}
Sriram et al.~\cite{sriram2024local} leveraged local LLMs for secure in-system task automation via prompt-based classification, preserving privacy but reporting a 14\% misclassification rate and confining access to a single local machine. Kuchlous and Kadaba~\cite{kuchlous2020intent} developed short-text intent classification for a therapy chatbot restricted to four fixed discourse categories, limiting generalization to open-ended personal document queries. Puspitasari et al.~\cite{puspitasari2026intent} proposed an intent-aware RAG framework with semantics-preserving chunking, but assume relevant information is localized within single chunks and do not address original file delivery--motivating IntentCloud's open-ended intent parsing for personal file re-finding.

\subsection{Edge AI, Hardware Acceleration, and Privacy-Preserving Deployment}
Nan et al.~\cite{nan2026dsmr} proposed DSMR, an intelligent file query system integrating NLU with IR, but requires dual NVIDIA A100 GPUs and 128~GB RAM--well beyond consumer-grade hardware. Holubiev et al.~\cite{holubiev2024agents} examined autonomous agents for knowledge management in contact centers; recursive reasoning loops introduce substantial latency without quantitative IR benchmarking. Nickolls et al.~\cite{nickolls2008cuda} and Apple Inc.~\cite{apple2026mps} documented CUDA and Metal Performance Shaders (MPS) GPU acceleration backends, respectively; IntentCloud integrates automated hardware detection across CUDA, MPS, and CPU execution paths to support cross-platform local inference without fixed hardware assumptions.

\subsection{Hybrid Fusion, Reranking, and Research Gap}
To address the lexical--semantic gap identified across surveyed works, IntentCloud adopts complementary dense bi-encoder retrieval~\cite{karpukhin2020dense, reimers2019sentence}, sparse feature hashing~\cite{robertson2009probabilistic}, Reciprocal Rank Fusion (RRF, $k=60$)~\cite{cormack2009reciprocal}, and cross-encoder secondary reranking~\cite{nogueira2019passage} for precision refinement ($N \le 25$). Building on the hybrid blending evidence of Sawarkar et al.~\cite{sawarkar2024blended}, IntentCloud delivers a complete self-hosted architecture with calibrated abstention, authoritative document return, and cross-platform execution. \section{Methodology}

The proposed IntentCloud architecture is structured into five operational phases, depicted in Fig.~\ref{fig:architecture}. The entire system executes as an integrated service on local consumer hardware without external network transmission. This section describes the problem approach, system design, implementation workflow, and technical components aligned with our formal research objectives.

\subsection{Phase 1: Ingestion, Extraction, and Metadata Lineage Tracking}
Document ingestion supports multi-format file uploads (PDF, DOCX, TXT), providing an end-to-end processing pipeline beyond metadata-only systems~\cite{karthikeyan2025smart, douze2024faiss}. Unencrypted PDF streams are parsed natively using PyMuPDF (\texttt{fitz}), and Office documents via \texttt{python-docx}. If native parsing yields fewer than 100 characters (indicating scanned media), an automated Tesseract OCR fallback executes to eliminate silent extraction failures. Extracted text undergoes whitespace and Unicode normalization before segmentation via sliding character windows ($C = 1200$ characters, overlap $O = 200$). Before vector indexing, document-level embeddings are compared against existing vectors; if cosine similarity satisfies $\text{sim}(d_{\text{new}}, d_{\text{existing}}) \ge 0.95$, the document is suppressed as a duplicate to preserve storage and search fidelity. Crucially, the ingestion service extracts and records document metadata--including creation and modification timestamps ($t_{\text{modified}}$), file extension, content hash, version index ($v_d \in \mathbb{N}$), and parent document linkages ($d_{\text{parent}}$)--to establish explicit document-version lineage.

\subsection{Phase 2: Dual Semantic and Lexical Vector Representation}
To guarantee dual semantic abstraction and exact token recall without cloud API calls, each text chunk $c_i$ is mapped into two parallel vector spaces:

\subsubsection{Dense Semantic Embedding}
Chunk text is processed by a local Sentence-Transformers model (\texttt{all-MiniLM-L6-v2})~\cite{reimers2019sentence}, implementing the dense bi-encoder paradigm of Karpukhin et al.~\cite{karpukhin2020dense}, producing a normalized 384-dimensional continuous vector:
\begin{equation}
\mathbf{v}_{\text{dense}} = \text{Embed}_{\text{dense}}(c_i) \in \mathbb{R}^{384}, \quad \|\mathbf{v}_{\text{dense}}\|_2 = 1
\label{eq:dense}
\end{equation}
Dense vector search utilizes cosine distance, which simplifies to the dot product under $L_2$ normalization:
\begin{equation}
S_{\text{dense}}(q, c_i) = \langle \mathbf{v}_{\text{dense}}(q), \mathbf{v}_{\text{dense}}(c_i) \rangle
\label{eq:dense_sim}
\end{equation}

\subsubsection{Deterministic Sparse Feature Hashing}
To capture exact lexical tokens without requiring an external Lucene process, tokens are tokenized, stemmed, and projected into a fixed high-dimensional sparse vector space ($D = 1,000,003$) using universal MurmurHash3 hashing, approximating BM25-style lexical discrimination~\cite{robertson2009probabilistic} within a single embedded index:
\begin{equation}
\text{idx}(w) = \text{MurmurHash3}(w) \pmod D
\end{equation}
Each term weight represents log-normalized term frequency:
\begin{equation}
\mathbf{v}_{\text{sparse}}[j] = 1 + \ln(\text{tf}(w, c_i)), \quad \text{for } j = \text{idx}(w)
\label{eq:sparse}
\end{equation}
Both vector representations are indexed simultaneously into an embedded, in-process Qdrant vector engine residing directly in local NVMe/SSD storage, providing the persistence and serving layer absent in standalone libraries such as FAISS~\cite{douze2024faiss}.

\subsection{Phase 3: Query-Aware Intent Parsing and Lineage Conditioning}
When a user submits an unconstrained natural language query, an optional local lightweight Large Language Model (\texttt{llama3.2:1b} under Ollama) executes in JSON mode ($\theta = 0.1$), following privacy-preserving local inference paradigms~\cite{sriram2024local} beyond closed-set classifiers~\cite{kuchlous2020intent, puspitasari2026intent}. The model distills the raw query into a structured payload containing \texttt{topic} (core semantic subject), \texttt{keywords} (explicit entities), \texttt{intent\_type} (\texttt{find}, \texttt{compare}, \texttt{summarize}, \texttt{list}, \texttt{recent}, \texttt{version}), and temporal constraints.

To incorporate document recency and version lineage (Objective 3), the query engine dynamically conditions retrieval scores on document metadata:
\begin{equation}
S_{\text{meta}}(d \mid q) = \lambda_t(q) \cdot T(d, q) + \lambda_v(q) \cdot V(d, q)
\end{equation}
where $T(d, q) = \exp(-\gamma \cdot \Delta t)$ applies exponential recency decay over elapsed time $\Delta t$, and $V(d, q)$ adjusts candidate ranking to favor latest revisions for operational queries or isolate historical parent versions when historical intent is parsed. If the local LLM daemon is offline, rule-based keyword extraction and metadata parsing execute seamlessly without blocking retrieval.

\subsection{Phase 4: Hybrid Retrieval, Fusion, and Reranking}

\subsubsection{Parallel Candidate Retrieval}
Given query $q$, the system dispatches parallel asynchronous vector searches to Qdrant:
\begin{align}
\mathcal{L}_{\text{dense}} &= \text{Search}_{\text{dense}}(q, \text{top\_k}=20) \\
\mathcal{L}_{\text{sparse}} &= \text{Search}_{\text{sparse}}(q, \text{top\_k}=20)
\end{align}
yielding two ranked lists of candidate chunks: $\mathcal{L}_{\text{dense}} = [d_1^{(d)}, \dots, d_{20}^{(d)}]$ and $\mathcal{L}_{\text{sparse}} = [d_1^{(s)}, \dots, d_{20}^{(s)}]$.

\subsubsection{Reciprocal Rank Fusion}
To combine candidates across disparate scoring regimes, we compute the fused RRF score for every unique candidate $d \in \mathcal{L}_{\text{dense}} \cup \mathcal{L}_{\text{sparse}}$ using Eq.~\eqref{eq:rrf} with $k=60$~\cite{cormack2009reciprocal}, following the hybrid blending rationale demonstrated by Sawarkar et al.~\cite{sawarkar2024blended}. If candidate $d$ does not appear in list $m$, its reciprocal term is set to zero. The unified candidate pool $\mathcal{C}_{\text{RRF}}$ is sorted descending by $\text{RRF\_Score}(d)$, and the top $N=25$ candidates are forwarded to the cross-encoder.

\subsubsection{Cross-Encoder Precision Reranking}
A pre-trained cross-encoder (\texttt{cross-encoder/ms-marco-MiniLM-L-6-v2})~\cite{nogueira2019passage} processes pairs $(q, d)$ for each candidate $d \in \mathcal{C}_{\text{RRF}}$:
\begin{equation}
z(q, d) = \text{CrossEncoder}(q \circ d) \in \mathbb{R}
\end{equation}
where $\circ$ represents sequence concatenation with special classification separation tokens. The raw output logit $z(q, d)$ is mapped to a normalized confidence score via the logistic sigmoid function:
\begin{equation}
s_{\text{ce}}(q, d) = \sigma(z(q, d)) = \frac{1}{1 + e^{-z(q, d)}} \in (0, 1)
\label{eq:sigmoid}
\end{equation}
The cross-encoder execution engine features automated hardware detection, utilizing Apple Silicon Metal Performance Shaders (MPS)~\cite{apple2026mps}, NVIDIA CUDA~\cite{nickolls2008cuda}, or optimized multi-threaded CPU SIMD execution, addressing the limited cross-platform inference support identified in the literature survey.

\subsubsection{File-Level Deduplication}
Because multiple candidate chunks may originate from the same parent document, candidates are grouped by \texttt{file\_id}. The system retains only the highest-scoring chunk per file, ensuring that the returned Top-3 results represent three distinct, relevant documents.

\subsubsection{Explainable Matched-Snippet Attribution}
For the top-ranked document candidates, the system splits the winning text chunk into discrete sentences $\{s_1, s_2, \dots, s_p\}$. The cross-encoder scores each sentence against query $q$:
\begin{equation}
s^* = \arg\max_{s_j} \sigma(\text{CrossEncoder}(q \circ s_j))
\end{equation}
Sentence $s^*$ is highlighted in the user interface as the verified textual citation justifying retrieval, providing human-interpretable ``Why this matched'' rationales.

\subsubsection{Calibrated Out-of-Domain Confidence Gating}
To prevent false-positive hallucinations on irrelevant or unindexed queries--a failure mode traced in RAG embedding studies~\cite{cejas2025retrieval}--the top candidate's cross-encoder score is evaluated against an empirically calibrated threshold $\tau = 0.40$:
\begin{equation}
\text{Decision}(q) = 
\begin{cases} 
\text{Serve}(\text{Top-3}), & \text{if } \max_{d} s_{\text{ce}}(q, d) \ge \tau \\ 
\text{Abstain}, & \text{otherwise}
\end{cases}
\label{eq:gate}
\end{equation}
where an $\text{Abstain}$ decision returns zero result cards accompanied by a ``No confident match found'' notification banner.

\subsection{Phase 5: Self-Hosted Service and Authoritative File Delivery}
Unlike conventional generative systems that return synthesized summaries, IntentCloud delivers the authoritative original document file. The service coordinates upload ingestion, indexing, retrieval, and file serving within a unified, self-hosted FastAPI and Next.js architecture. When a user requests a retrieved file, the server streams the exact source bytes (\texttt{uploads/\{file\_id\}.\{ext\}}) over a secure, outbound-only encrypted Cloudflare Zero-Trust tunnel (\texttt{https://*.trycloudflare.com}) without opening inbound firewall ports, satisfying strict local data sovereignty and meeting a predefined response-time target of $\le 15$ seconds under realistic user workloads.

\section{Experimental Evaluation}

\subsection{Experimental Setup and Benchmark Corpus}
To rigorously validate the architecture, an empirical benchmark corpus was curated across five core technical domains: (1)~\textit{Distributed Systems} (Apache Kafka stream processing, replication protocols, backpressure, partition sizing); (2)~\textit{Software Architecture} (microservices design patterns, circuit breakers, event-driven architectures, API gateways); (3)~\textit{Machine Learning \& NLP} (transformer self-attention, CNNs, backpropagation calculus); (4)~\textit{Information Retrieval} (BM25 formulations, dense passage retrieval, cross-encoder attention mechanics); and (5)~\textit{Systems Documentation} (IntentCloud blueprints and business reviews).

\subsection{Evaluation Query Suite}
A standardized benchmark suite of 42 natural language queries was constructed across four distinct operational categories:
(i)~\textit{Exact Lexical Matches} (10 queries targeting specific filenames, error strings, and technical methods);
(ii)~\textit{Semantic Paraphrases} (12 queries expressing conceptual intent without literal vocabulary overlap with document titles);
(iii)~\textit{Multi-Concept Queries} (10 thematic queries requiring joint reasoning across intersecting topics); and
(iv)~\textit{Out-of-Domain Negative Controls} (10 queries with zero semantic or lexical overlap with the corpus, e.g., cooking recipes, gardening, sports schedules, skincare routines).

\subsection{Evaluation Metrics}
The evaluation measures five standardized information retrieval metrics:
(1)~\textbf{Top-1 Accuracy}: percentage of positive queries where the rank-1 retrieved document matches ground truth;
(2)~\textbf{Top-3 Accuracy}: target file appears within the top-3 unique results;
(3)~\textbf{Mean Reciprocal Rank (MRR)}: $\text{MRR} = \frac{1}{|Q_+|} \sum_{i=1}^{|Q_+|} \frac{1}{\text{rank}_i}$, the average reciprocal rank of the target document;
(4)~\textbf{Negative Rejection Rate}: percentage of out-of-domain queries successfully rejected by the confidence gate ($\tau = 0.40$); and
(5)~\textbf{Average Latency}: total elapsed execution time per query across pooling, RRF, cross-encoder reranking, and citation generation.

\subsection{Baseline Models}
We benchmark the proposed architecture against three configurations:
\textbf{Mode A} (sparse lexical baseline using feature-hashed vector retrieval, $D = 10^6$~\cite{robertson2009probabilistic});
\textbf{Mode B} (dense semantic baseline using 384-d bi-encoder retrieval, \texttt{all-MiniLM-L6-v2}~\cite{reimers2019sentence, karpukhin2020dense}); and
\textbf{Mode C} (proposed full hybrid pipeline combining dual-stream pooling, RRF fusion~\cite{cormack2009reciprocal, sawarkar2024blended}, cross-encoder reranking~\cite{nogueira2019passage}, and confidence gating~\cite{cejas2025retrieval}).

\section{Results and Expected Outcomes}

\subsection{Quantitative Retrieval Performance}
The empirical results across all 42 evaluation queries are summarized in Table~\ref{tab:benchmark}. The proposed hybrid pipeline (Mode~C) achieves \textbf{87.5\% Top-1 accuracy} and a Mean Reciprocal Rank of \textbf{0.932}, representing a \textbf{+21.9 percentage-point improvement in Top-1 accuracy} over the dense bi-encoder baseline (Mode~B, 65.6\%) and substantially surpassing the sparse keyword baseline (Mode~A, 38.7\%), satisfying the baseline superiority requirements of Project Objective 1. Furthermore, Mode~C achieves 100.0\% Top-3 accuracy, guaranteeing that the target document is invariably returned within the top three positions. Crucially, the calibrated confidence gate ($\tau = 0.40$) achieves a 100\% true-negative rejection rate across all 10 out-of-domain control queries (with candidate scores between 7--15\%), reliably suppressing result cards and issuing a ``No confident match found'' directive to prevent false-positive hallucination.

\subsection{Ablation Analysis: Lexical vs. Semantic Complementarity}
Query error-trace analysis highlights the complementary failure modes of isolated retrieval streams. On the query \textit{``Compare BM25 probabilistic ranking with dense passage retrieval''}, the dense-only baseline~\cite{karpukhin2020dense} retrieved a generic neural network paper due to broad conceptual overlap; however, sparse feature hashing localized the exact term ``BM25''~\cite{robertson2009probabilistic}, enabling RRF~\cite{cormack2009reciprocal} to elevate the comparative target into the reranking pool. Conversely, on the semantic query \textit{``Where are the notes discussing microservice fault tolerance and circuit isolation?''}, the sparse baseline failed due to vocabulary mismatch with document phrases (``resilience patterns'' and ``service degradation''), whereas the dense encoder~\cite{reimers2019sentence, vnrk2025semantic} matched conceptually (cosine similarity 0.81). By fusing both streams via RRF ($k=60$)~\cite{cormack2009reciprocal, sawarkar2024blended}, Mode~C achieved 100\% candidate recall prior to cross-encoder reranking~\cite{nogueira2019passage}.

\subsection{Computational Latency and Hardware Scalability}
End-to-end latency averaged 2,401~ms on the 42-query suite under local Apple Silicon MPS acceleration~\cite{apple2026mps} for 25 candidates, dropping below 350~ms on warm-cache queries. Execution breaks down into sparse feature hashing ($\approx 18$~ms), dense embedding and vector search ($\approx 42$~ms), RRF fusion ($< 2$~ms), cross-encoder scoring ($\approx 1,320$~ms), and sentence snippet attribution ($\approx 75$~ms). The computational footprint operates entirely in local workstation memory without cluster-scale GPU dependencies~\cite{nan2026dsmr} or cloud API roundtrips~\cite{krishnan2025semantic, jacob2024chatgpt}, with automated execution across CUDA~\cite{nickolls2008cuda}, MPS~\cite{apple2026mps}, and CPU.

\section{Conclusion and Future Work}
This paper presented IntentCloud, an intent-aware, local-first document retrieval system designed to eliminate cloud privacy exposure while solving the lexical-semantic mismatch dilemma in personal document search. By projecting documents into complementary dense semantic and sparse feature-hashed representations, unifying candidates via Reciprocal Rank Fusion ($k=60$), and applying secondary cross-encoder precision reranking with calibrated confidence gating ($\tau = 0.40$), the architecture achieves 87.5\% Top-1 accuracy and 0.932 MRR on a 42-query diagnostic benchmark, with 100\% out-of-domain rejection via strict abstention--addressing synthesis-only and false-positive limitations identified across existing personal document retrieval and RAG systems.

Future work will advance this research across four core trajectories aligned with our extended capstone objectives:
(1)~\textit{Corpus Expansion and Multi-Graded Evaluation}: expanding the benchmark corpus to at least 150 mixed-format documents (PDF, DOCX, TXT) across multiple technical domains with graded relevance annotations and statistical significance testing (Objective~1);
(2)~\textit{Query-Aware Recency and Version Lineage Modeling}: operationalizing temporal decay functions and parent-child version graph traversal to distinguish between original, historical, and latest document versions (Objective~3);
(3)~\textit{Adaptive Interaction Layer and Reranker Bypassing}: capturing local user feedback signals (dwell time, clicks, downloads) to dynamically bypass cross-encoder computation on high-confidence queries without external data transmission (Objective~5); and
(4)~\textit{Resource-Constrained Edge Characterization}: deploying the complete pipeline onto Raspberry Pi-class edge hardware with active cooling, evaluating model optimization and INT8 quantization, and systematically profiling retrieval quality, latency, memory consumption, thermal behaviour, throughput, and energy consumption to establish the quality--latency--energy Pareto trade-off (Objective~6).
